# Shared UI/UX Guidelines (Tailwind + Shadcn)

This document ensures that App A, App B, and App C all share the exact same look and feel, based directly on the approved design mockups.

AI Agents building these applications must strictly adhere to these visual constraints.

---

## 1. Global Aesthetic
The core aesthetic is clean, hyper-modern, light-mode enterprise software. 
*   **Mode**: Light Mode by default.
*   **Spacing**: Generous whitespace. Forms and cards should not feel cramped.
*   **Backgrounds**: The main application background should be a very soft off-white or light gray (e.g., `bg-slate-50` or `bg-gray-50`), allowing white Cards/Modals to "pop" off the screen.

---

## 2. Shadcn UI Component Overrides

When initializing or using Shadcn components, ensure the following visual styles match the mockup exactly:

### 2.1. Cards (div/Container styling)
*   **Background**: Pure white (`bg-white`).
*   **Border**: A subtle, thin border (`border border-slate-200`).
*   **Radius**: Smoothly rounded corners (`rounded-xl` or `rounded-2xl`).
*   **Shadow**: A very soft, diffuse drop-shadow (`shadow-sm` or `shadow-md`).

### 2.2. Inputs (Text Fields, Password, Select)
*   **Focus State (CRITICAL)**: When an input is focused, it MUST have a strong black or very dark gray border outline (e.g., `focus:ring-2 focus:ring-black focus:border-black` or `focus-visible:ring-black`). *See the "Username" field in the mockup.*
*   **Idle State**: When not focused, the border should be very subtle and light (`border-slate-200`). *See the "Password" field in the mockup.*
*   **Padding**: Generous vertical and horizontal padding to make the inputs feel substantial (e.g., `py-3 px-4`).
*   **Radius**: Matching rounded corners (`rounded-md` or `rounded-lg`).

### 2.3. Buttons
*   **Primary Button**: Sold black background with white text (`bg-black text-white hover:bg-black/90`). *See the "Log in" button in the mockup.*
*   **Radius**: Matching rounded corners (`rounded-md` or `rounded-lg`).
*   **Height**: Should match the height of the input fields perfectly.

### 2.4. Typography
*   **Font Family**: A clean sans-serif (e.g., `Inter`, `Geist`, or default Tailwind sans).
*   **Headings**: Bold and dark (`text-slate-900 font-bold`). *See the "Log in" title.*
*   **Subtitles/Help Text**: Softer gray text (`text-slate-500 text-sm`). *See the "Enter your username..." text.*
*   **Labels**: Deep black/gray, strongly weighted (`font-medium text-slate-900`). *See the "Username" and "Password" labels.*

---

## 3. Layout Examples

### Centered Auth Forms (App A, B, C)
When building the Login, Activation, or Setup screens, use this exact layout structure:
1.  A full-screen container (`min-h-screen flex items-center justify-center bg-slate-50`).
2.  A centered Card component (`w-full max-w-md p-8 bg-white rounded-2xl shadow-md border border-slate-200`).
3.  A header section (`space-y-2 mb-6`).
4.  A form section containing the vertical inputs with distinct labels.

### Inner Application Layouts (Dashboard, Lists)
Once logged in, follow a standard SaaS layout:
1.  Top Navbar or Left Sidebar (matching the `bg-black` primary color for active states or subtle slate for idle).
2.  Main content area (`bg-slate-50 p-6 or p-8`).
3.  Data tables and forms should be wrapped in the same clean White Cards described in 2.1.

---

## 4. Instructions for Agents
When writing React code, do not write custom raw CSS in `.css` files. 
You must achieve all these looks using **Tailwind utility classes** applied directly to standard Shadcn components, or by modifying the `globals.css` theme variables generated by the Shadcn `init` command to match these specifications (e.g., setting primary to `hsl(0 0% 9%)` for the black buttons).
